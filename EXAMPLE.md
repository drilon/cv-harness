# CV TAILORING HARNESS: SAM CARTER

> **This is a complete FICTIONAL example.** Sam Carter does not exist. Every employer, number, and fact below is invented to show what a filled harness looks like in a different profession (data analytics). Do not copy the facts; copy the shape.

**Purpose:** Single source of truth for AI agents producing a tailored, ATS-compliant CV and cover letter for Sam Carter against a specific job posting.

**Prime directive:** Every line you write must be defensible by the candidate in a live interview. Tailor by SELECTION and EMPHASIS, never by invention. If the posting demands something not in this file, flag the gap to the user; do not fabricate.

**Second directive:** Honest is the floor, not the goal. The goal is an interview. A reader who skims for ten seconds must be able to see that Sam meets this posting's top requirements. Relevance to THIS posting decides what leads, what gets space, and what gets cut.

## 1. WORKFLOW

1. Read the posting. Extract exact job title, role type and seniority, must-haves (up to 6) vs nice-to-haves, exact keywords, the problem this hire solves, region, hard gates (degree, clearance, tools, location), and application instructions.
2. Check gates against Section 8. If a gate fails, tell the user before drafting.
3. Build the fit map and show it before drafting: `Requirement | Must-have or nice-to-have | Best evidence | MATCH, BRIDGE, or GAP`. Verdict: STRONG (every must-have MATCH or BRIDGE, most MATCH), STRETCH (one must-have GAP, or most are BRIDGE), LONG SHOT (two or more must-have GAPs). On LONG SHOT, stop and ask.
4. Pick the playbook (Section 9). Build by subtraction from Section 6. Space follows relevance to the posting.
5. Win the top third: headline, summary, and the first two bullets of the most relevant role answer the top 3 must-haves. Most relevant bullet first in every role.
6. Mirror the posting's exact wording where Section 7 supports it. Every must-have keyword appears in a bullet with evidence, not only in the skills list.
7. Cover letter and outreach note per Section 11. Screening questions per Section 14.
8. QA per Section 12, including the keyword coverage table.
9. Deliver in the format the posting asks for, else `CV_Sam_Carter_{Company}.docx`, plus a plain-text copy for web forms.

Example fit map rows, for a posting that asks for SQL, experimentation, Tableau, and team management:

| Requirement | Type | Best evidence | Rating |
|---|---|---|---|
| Advanced SQL | Must-have | 6.1 dbt layer, 41 models | MATCH |
| A/B testing | Must-have | 6.1 experiments and playbook | MATCH |
| Tableau | Must-have | Looker and Metabase (6.1, 6.2); no Tableau | BRIDGE: same job, different BI tool; say so plainly |
| Managing a team of analysts | Nice-to-have | Mentors 2, coordinated 3; never line-managed | GAP for "managing"; state mentoring and coordination only |

Verdict: STRONG. Flag Tableau and management to the user.

## 11. COVER LETTER & OUTREACH GUIDE

**Cover letter.** One page, 250-350 words. Hook for playbook A: the 2024 pricing analysis and its adopted recommendation. Hook for B: the 41-model dbt layer and the 3-days-to-4-hours board pack. Proof paragraph maps 2-3 posting requirements to registry facts. The letter names the problem this hire solves and the one time Sam solved it before; it never restates the CV. Address the no-people-management gap only if the posting is explicitly a management role (in which case, flag to user first: is this posting even a fit?).

**Outreach note.** 60-90 words, plain text. One sentence on the role, one registry fact that matches the top requirement, one specific ask. Leave `[NAME]` for the recipient; never guess a name or a shared connection.
